# Excel HR Consultancy — Recruitment Intelligence Platform

An AI-assisted recruitment platform built for **Excel HR Consultancy** to streamline the recruitment lifecycle — from job creation and candidate intake to CV screening, recruiter decision-making, candidate outreach, AI calling, and final reporting.

The platform is designed around one core principle:

> **AI assists recruitment decisions. Human recruiters remain in control.**

---

## Overview

Traditional recruitment workflows often involve multiple disconnected tools for job requirements, candidate profiles, CV screening, communication, recruiter decisions, and reporting.

The Excel HR Consultancy Recruitment Intelligence Platform brings these activities into a single structured workflow.

### Recruitment Workflow

JD Setup  
↓  
Initial Candidate Screening  
↓  
CV Upload & Parsing  
↓  
AI-Assisted CV Screening  
↓  
Recruiter Finalisation  
↓  
WhatsApp Outreach  
↓  
AI Calling  
↓  
Final Recruitment Report

## Core Features

### 1. Job Description Setup

Recruiters can create recruitment requirements containing:

- Client name
- Job title
- Department
- Location
- Work mode
- Minimum and maximum experience
- Maximum notice period
- Education requirements
- Full job description
- Required skills
- Preferred skills
- Knockout criteria
- Qualifying score
- Custom scoring weights

Recruitment records are stored in Supabase for use throughout the workflow.

---

### 2. Initial Candidate Screening

Recruiters can add candidate information such as:

- Name
- Email
- Phone number
- Current designation
- Current employer
- Total experience
- Current location
- Preferred location
- Notice period
- Education
- Salary information
- Skills

Optional candidate profile screenshots can also be uploaded.

The system includes duplicate detection using normalized email addresses and phone numbers.

The recruiter manually decides which candidates should proceed to CV screening.

---

### 3. CV Upload & Parsing

Selected candidates can upload or be assigned CVs in:

- PDF
- DOCX

Candidate documents are stored in private Supabase Storage.

The parsing pipeline extracts real information from the uploaded document instead of generating placeholder candidate information.

Parsed information can include:

- CV text
- Email
- Phone number
- Skills and candidate evidence used by the screening pipeline

Scanned/image-only documents are treated as missing text rather than generating artificial information.

---

### 4. Custom CV Screening Engine

The final candidate score is generated by our own screening pipeline rather than relying on an external LLM to make the hiring decision.

The model service is built using:

- Python
- FastAPI
- Sentence Transformers
- Semantic embeddings
- Deterministic scoring logic

Current embedding model:

`sentence-transformers/all-MiniLM-L6-v2`

The screening engine evaluates factors including:

- Required skills
- Preferred skills
- Experience
- Role relevance
- Education
- Location
- Notice period

Each recruitment requirement can assign its own scoring weights.

---

## Explainable Candidate Scoring

The platform does not only display an overall percentage.

Each assessment can contain:

- Overall score
- Recommendation
- Confidence score
- Missing-information count
- Individual scoring components
- JD requirement
- Candidate value
- Evidence from the CV
- Component score
- Configured weight
- Score contribution
- Component confidence

This creates an auditable and explainable screening process.

### Recommendations

The model can classify an assessment as:

- Strong Match
- Review Recommended
- Weak Match
- Insufficient Information

These are recommendations — not automatic hiring decisions.

---

## Human-in-the-Loop Recruitment

Recruiters retain final control over candidate progression.

During candidate finalisation, the recruiter can:

- Review the AI score
- Inspect scoring evidence
- Approve a candidate
- Reject a candidate
- Agree or disagree with the AI recommendation
- Record an override reason
- Add recruiter notes
- Correct extracted information
- Verify the candidate's phone number
- Record WhatsApp consent

The AI recommendation and recruiter decision are stored separately for auditability.

---

## WhatsApp Outreach

The platform contains the workflow structure for candidate WhatsApp outreach.

The planned integration is with **WATI / WhatsApp Business messaging**.

The communication system is designed to track statuses such as:

- Ready
- Queued
- Sent
- Delivered
- Read
- Replied
- Interested
- Not Interested
- Failed
- Opted Out

> **Current status:** The WhatsApp UI and database communication structure exist, but the production WATI integration is still being connected.

No message is represented as successfully sent unless a real provider confirms it.

---

## AI Calling

Candidates who successfully pass recruiter review and the outreach workflow can later enter the AI calling stage.

The calling architecture supports:

- English
- Hindi
- Hinglish
- Call scheduling
- Provider call IDs
- Call status tracking
- Transcript references
- Recording references
- Provider errors

Potential call states include:

`scheduled → initiated → ringing → answered → completed`

and failure states such as:

`no_answer`, `busy`, `failed`, and `cancelled`.

> **Current status:** The calling workflow and database architecture are implemented, but a production AI calling provider has not yet been connected.

The application does not simulate successful calls.

---

## Final Recruitment Report

The reporting layer consolidates recruitment information across the complete workflow.

The report can contain:

### Job Information
- Client
- Position
- Department
- Location
- Experience requirements
- Required skills
- Preferred skills
- Knockout criteria
- Qualifying score

### Candidate Information
- Candidate profile
- CV screening result
- AI recommendation
- Confidence
- Scoring evidence
- Recruiter decision
- Override reason
- Recruiter notes
- WhatsApp status
- AI calling status

The report keeps AI assessments and human decisions separate.
